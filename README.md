# QuietShield — Brave's ad-blocking engine as a Chrome extension

*Not affiliated with or endorsed by Brave Software. "Brave" is a trademark of Brave Software, Inc.*

A Chrome Manifest V3 extension that reproduces Brave Shields' ad and tracker blocking using
**Brave's own engine, [adblock-rust](https://github.com/brave/adblock-rust)**, Brave's default
filter lists, and ports of Brave's cosmetic-filtering scripts.

## Install

**[Step-by-step install guide](https://arjun-vegeta.github.io/QuietShield/)** — about a minute:

1. Download [`quietshield.zip`](https://github.com/arjun-vegeta/QuietShield/releases/latest/download/quietshield.zip) and unzip it.
2. Open `chrome://extensions` and turn on **Developer mode**.
3. Drag the unzipped `quietshield` folder onto the page.

Releases are built by GitHub Actions with the latest Brave filter lists (push a `vX.Y.Z` tag matching
`package.json`). GitHub installs check for new releases daily (can be turned off in the popup).

## How it maps Brave Shields onto MV3

| Brave (brave-core) | This extension |
|---|---|
| `AdBlockEngine::matches()` on every request via a URLLoaderFactory proxy | adblock-rust parses the lists at **build time**; `compiler/` converts each filter to `declarativeNetRequest` rules (≈21k standard + 16k aggressive rules after merging) |
| Two engines: default lists (`first_party_protections`) vs additional lists | Standard rulesets add `domainType: thirdParty` to default-list blocks; `*-aggressive` rulesets add the first-party half back |
| `$redirect` stub responses | DNR `redirect.extensionPath` to uBO/Brave resources in `build/war/` (`use_dynamic_url`) |
| `$removeparam`, `$csp` | `queryTransform.removeParams`, `modifyHeaders` (Brave ignores default-engine removeparam; so do we) |
| Sync `UrlCosmeticResources` before page JS | `url_cosmetic_resources` precomputed for all ~62k hostnames rules mention → `chrome.storage.local`, read at `document_start` |
| `content_cosmetic.ts` + `procedural_filters.ts` | Ported in `extension/src/cosmetic.js`; Brave's procedural engine vendored unchanged (MPL-2.0) |
| `hidden_class_id_selectors` IPC to the browser | **adblock-rust compiled to WebAssembly** in the service worker (`engine-wasm/`), ~25 ms cold start |
| Scriptlets injected into the main world before page scripts | MAIN-world `document_start` content scripts, sharded by site; per-host call lists generated by the engine against stub resources so function bodies ship once |
| Standard vs Aggressive, per-site Shields down | popup → rulesets toggle, `allowAllRequests` dynamic rule + content-script excludes |

## Build

```sh
npm install
npm run fetch   # Brave list catalog + default lists, Brave resources, uBlock Origin checkout
npm run build   # compiler → DNR rules, cosmetic data, scriptlet shards; wasm engine; manifest
npm run package # dist/quietshield-<version>.zip (+ dist/quietshield.zip)
```

Requires Rust (stable + `wasm32-unknown-unknown`), `wasm-bindgen-cli 0.2.129`, Node 22+.
Load `extension/` as an unpacked extension (or `tests/launch-cft.sh` for Chrome for Testing).

## Verified against Brave 1.97 (Chromium 155), same pages side by side

- **Brave QA pages** (dev-pages.brave.software): scriptlets (main, local and remote frames),
  first-/third-party network policy in Standard and Aggressive — identical results.
- **Cosmetic parity page** (`tests/pages/cosmetic.html`, 3 host setups incl. `$generichide`
  exceptions): 24/24 element states identical.
- **10 news/media sites**: blocked request counts within a few of Brave, zero visible ad slots.
- **REA passive capture of cnn.com**: same third-party origins blocked, byte-identical
  surrogate scripts, identical DOM inventory.
- **Detection techniques** (`tests/pages/detect.html`): same results as Brave except one —
  redirected surrogates have no Resource Timing entry (Brave serves them in place).

`tests/compare.mjs`, `tests/probe.mjs`, `tests/isolated.mjs`, `tests/sw-eval.mjs` drive the
browsers over CDP; `cargo test` covers the converter.

## Known gaps (MV3 platform limits) and how they're handled

- **CNAME uncloaking:** no DNS API, so AdGuard's cname-trackers map (MIT) is compiled into
  `cname` / `cname-aggressive` rulesets, keeping only hosts whose canonical tracker Brave's lists
  block. Like Brave, Standard mode uncloaks only third-party loads; Aggressive also first-party.
- **Surrogates are served by redirect** (no Resource Timing entry, unlike Brave's in-place stubs).
  A Resource Timing shim prototype lives in `research/rt-shim/`.
- **Regex filters:** Chrome's RE2 budget rejects ~40%; build-time rewrites gated against
  adblock-rust's 243k-request corpus (`scripts/regex-alternatives.mjs`) recover most of them.
- **Entity domains** (`domain=site.*`) are expanded to concrete suffixes (`compiler/src/entities.rs`).
- **Cross-site cookies:** optional popup toggle (Brave blocks them by default; Chrome needs the
  optional `privacy` permission). No ephemeral first-party storage and no fingerprint farbling
  (prototype in `research/farbling/`).
- Static rules update only with an extension update; see `research/updates/` for the
  skip-review pipeline design.
